# Spec hardening: design to the format's maximum, not the test shelf

**Status: the container maxima are filled from the Phase 1 parsers (2026-09-23): each row
gives the FIELD's width (what the format allows) and the census maximum over 33 discs
(what is common). Size to the first column.**

MiSTer_DVD shipped the same bug twice with different clothes: a table sized to the
largest disc on the shelf (64 VOBs; 128 cells) that a real disc then exceeded, silently.
The rule it earned is in `CLAUDE.md` "Design to the spec maximum": size every table,
counter and loop bound to what the FORMAT allows; where a hard limit forces a smaller
bound, discuss it, record it beside the code, and never truncate silently.

## Working rules

- A bound comes with a citation (the spec table, or the P1 parser that measured the
  field width) written beside the code.
- A bound that is ever hit is VISIBLE: a counter or flag a bench or telemetry can see.
- Measured libraries say what is common, not what is possible. Nine discs justify
  scoping decisions (no CAVLC, no field decoding) only because the unsupported cases are
  refused loudly.
- Update `conformance.md` in the same change that closes a gap.

## 🚩 Known deviations from the spec maximum (every one a decision taken with the user)

the bound, what it refuses, the code that makes the refusal visible, and what to do
about it.
